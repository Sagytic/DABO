## 2026-02-19 - Spring Data JPA N+1 and Sorting
**Learning:** JPA repositories fetching lists with `@ManyToOne` relationships (even with `FetchType.LAZY` or default `EAGER`) can cause severe N+1 query issues when accessed in a loop (e.g., `user.getNickname()`). Using `@EntityGraph(attributePaths = {"user"})` is a clean, annotation-based solution to force a join fetch without writing custom JPQL. Also, sorting in memory (`Collections.sort`/`reverse`) for large datasets is inefficient and memory-hungry compared to database-level sorting (`OrderBy...` in method name), which leverages DB indices.
**Action:** Always inspect loops in service methods for entity relationship access. Prefer `findAllByOrderBy...` over `findAll()` + `Collections.sort()`. Use `@EntityGraph` for eager loading in specific query methods.
